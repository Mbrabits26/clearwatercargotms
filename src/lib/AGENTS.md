# src/lib

- Doc extraction runs server-side in `extract.server.ts` (Lovable AI, strict JSON); spreadsheets are converted to CSV in the browser first. All document AI reads share `readDocJson`; carrier packets use `extractCarrierPacket` plus a review step before writing to carriers.
- `fixCarrierWithAi` reads carrier-docs + FMCSA, fills blanks only, preview-then-apply.
- Carrier duplicate matching/merging (DOT, MC, normalized name; fill blanks only) lives in `carrierMerge.ts`; cross-table merges run in `mergeCarriers` (carriers.functions.ts).

- Finance review assistant: AI (`planReview`) only turns a plain-English request into a filter; listing/matching is deterministic (`reviewAssistant.ts` + qbMatch) and every change needs row selection + confirm.
- Report/list exports share `reportExport.ts` (ReportSpec → plain black-on-white landscape jsPDF + CSV) via the `ReportExport` buttons; build specs from on-screen filtered rows and never include bank account numbers.
- Carrier pay due: `carrierPay.ts`, clock = loads.pod_received_at (trigger-stamped); carrier_paid_* finance-only (stamp_load_pay_fields); bank info in finance-only carrier_payment_accounts. Carrier page "Carrier payments" window (CarrierPayments.tsx) classifies via carrierPayState/carrierPaySummary; Mark paid finance-only.
- Reports' billing stage / invoice # come from `src/lib/reportBilling.ts` (paged qb_sync; a sent or linked customer invoice beats load status, except Paid/Cancelled).
- MCP tools in `mcp/`: read-only, use `supabaseForUser` so RLS applies as the OAuth caller; never the admin client. Consent at `src/routes/[.]lovable.oauth.consent.tsx`; /auth honors a validated `next` (oauthReturnPath) through password + Google. Browser-agent (WebMCP) tools live in the screen that renders the controls (Dispatch) and share its handlers.
- Billing automation: invoice packets merge client-side with pdf-lib (`invoicePacket.ts`); carrier rate cons are never default-ticked and carrier invoices never offered (they show carrier pay). Carrier invoice audit (`billAudit.ts`) compares to the latest signed, non-voided rate con snapshot; attaching before queuing creates a qb_sync bill with status 'hold', which is never sent until Send. Factoring remittance batches: `factoring.ts`.
- QB matching (`qbMatch.ts`): "high" needs a reference # (load #, invoice #, customer ref, shipper PO) plus customer or amount; customer+amount alone is only "probable" and ties are never auto-picked; `planMatches` pairs one invoice ↔ one load and flags possible QB doubles. Before creating a customer invoice, `deliverQueued` runs `findQbDuplicate` (qbDupGuard.ts) on recent QB invoices: a ref hit links instead of creating, an amount-only hit holds with "Possible duplicate" until "Send anyway" (force). QB invoice attachments are pulled read-only via `qbInvoiceFiles`/`qbImportFile` (QbFilesPanel) and copied onto loads once (tagged qb<attachableId>).
- qb_sync.deductions: amount gross, net=invoiceNet, QB minus lines. qb_sync.attachments go once (attachments_sent); qbSyncNow first runs `autoAttachPods` so load PODs (`isPodDoc`) join unsent customer invoices and, for loads marked pod_received, already-sent ones (uploaded onto the existing QB invoice, never a new one).
- @tags: saveMentions writes chat_mentions with client-made ids (authors can't read them back); the bell alerts on them live and catches up unread ones on open; load-note tags are also emailed by `emailNoteMentions` (email_mentions pref).
- Load doc deletes go only through `deleteLoadDoc` (staff, server-side): refuses signed rate cons and bill carrier invoices, logs to deletion_log, drops unsent QB picks, clears pod_received when no POD remains.
